# Phase 5 통합 검증 계획

2026-10-30 사용자 Phase 4 승인 및 Phase 5만 수행 지시. 신규 사업 기능·실거래/실서버·[F] 확장은 추가하지 않는다. 통합 검증 중 확인한 결함/스타일만 수정한다.

1. 원본 SSRD 기능/정량 수용, SSAD OP-01~05, PDF 앱 UI 참조와 현 구현의 경계 재확인.
2. viewport 요청과 실제 innerWidth/innerHeight 일치 후 320×800 / 360×800 / 390×844 / 430×932 / 1280×900 검사. 가로 넘침·모바일 전체 폭·PC390px 중앙·하단 탭 정렬·입력/링크 이름을 점검한다. 결과/조언/기록/영상/신청은 실제 생성 상태도 별도 확인.
3. 홈→설문→결과/조언→추천→상품→가상 구독→설정 삭제, 기기→동기화→기간/상세→영상 동의/모의 분석을 실제 클릭한다. 수정/삭제/새로고침/없는 ID 이후 과거 결과가 재생성되지 않는지 확인한다.
4. ONRQ-01~04 각각 3개 이상 사례를 실제 실행 증거에 매핑한다. UI-03 연결/영상/가상 주문의 대기·정상 Mock 완료·실패 9상태를 구분한다. 주문 정상도 실제 주문 성공으로 집계하지 않는다.
5. 화면 이동/설문 Mock/영상 Mock 각각 30회, 요청 클릭 시작부터 DOM visible 확인까지 제어 도구 벽시계 시간을 측정한다. p95는 오름차순 ceil(0.95*n) 위치. 도구 통신·자동화 대기 포함이며 렌더 완료/실기기/네트워크·실제 AI 성능을 나타내지 않는 보수적 로컬 프록시 측정이다. 원본 LOS의 실서비스 수용을 대체하지 않는다.
6. 기본 키보드·label·제목/초점·비진단 고지·외부 새 탭 알림/안전 속성·신규 비활성 이유를 확인한다. 전문가1회/사용자5명/실모바일 기기/서버 개인정보·암호화 검수는 수행할 수 없으면 Not tested로 명시한다.
7. 누적 단위 테스트/타입/프로덕션 빌드·실제 번들의 개발 시나리오 제거·원본 해시·저장/외부 API 경계 검사. README/추적표/결정/최종 QA 보고/게이트 갱신.

판정은 Pass(명시된 Mock/웹 범위), Partial(실제 근거/예외 부족), Not tested(실행/외부 검수 미수행), Fail(실제 결함)을 구별한다. 미검증을 통과로 바꾸지 않는다. 마지막 게이트는 Awaiting approval로 두고 중단한다.
