# UI/UX 및 화면 설계 기준

## 브랜드/디자인 출처
최종 기획서 PDF **p.12(설문/결과), p.14(홈), p.20(양치 점수·이력), p.21~22(팁 추천/조언)**의 스마트폰 목업을 우선 참조한다. **슬라이드 전체가 아닌 슬라이드 속 앱 화면**을 참고한다. 실제 원본의 색상·폰트·아이콘을 확인한 뒤 공통 디자인 토큰으로 정리한다. 외부 참고 이미지로 원본을 대체하지 않는다.

## 반응형 정책
- 기준 viewport 390×844 CSS px, 320~430px 최소 검증. 가로 스크롤 금지.
- PC 브라우저: 앱 컨테이너 max-width 390px, 중앙 배치. 모바일: width 100%, 별도 스마트폰 프레임 없음.
- 세로 스크롤, 안전 영역(safe-area-inset), 터치 목표 크기, 키보드 노출 시 입력 영역을 고려한다.
- 명확한 상단 헤더/뒤로가기/하단 탭바. 실제 탭 구성은 Phase 0에서 확정해 승인받는다.

## 인터랙션 원칙
- 모든 CTA는 화면 이동, 상태 변경, 검증 또는 설명 가능한 비활성 중 하나에 해당해야 한다.
- 테스트 응답이 바뀌면 결과/조언/추천이 일관되게 바뀌어야 한다.
- 분석/구독/동기화 로딩은 명시하고 실패를 재현할 수 있어야 한다.
- 차트, 수치 및 예시 이미지에는 데모 데이터를 실제 측정치로 오인하지 않도록 표시한다.
- 접근성: 입력 label, 초점 표시, 적절한 대비, 키보드 조작 가능성.

## Phase 0 디자인 산출물
Codex는 코드 작성 전에 `docs/SCREEN_MAP.md`에 화면별 목표, 네비게이션 다이어그램(텍스트 또는 Mermaid), 기능 ID, 주요 컴포넌트, 로딩/빈화면/오류 상태를 작성한다. 사용자 승인 후 구현한다.
