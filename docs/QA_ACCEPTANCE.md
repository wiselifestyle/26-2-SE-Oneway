# 검증/수용 기준 (QA)

## 공통 검사
- 정상/예외 시나리오 각각 실행 결과와 스크린샷 또는 검증 로그를 남긴다.
- 브라우저에서 실제 클릭해 주요 버튼·뒤로가기·탭 이동을 검증한다. 브라우저 자동화 도구가 없으면 미검증으로 표시한다.
- viewport 390×844, 360×800, 최소 320px 너비에서 가로 스크롤/겹침/잘림 여부 확인.
- 타입 검사, lint(설정 시), 빌드, 테스트(설정 시) 실행 및 결과 기록.
- 실패 기능을 구현된 것으로 보고하지 않는다. 가상 데이터임을 분명히 표시한다.

## SSAD 운영 흐름 검사
- OP-01: 설문→평가/권고→표시; 입력 누락·저신뢰 거부.
- OP-02: 기기 연결→동기화→중복 처리→추이; 연결 및 최근 동기화 상태.
- OP-03: 영상 동의→선택→모의 분석→조언; 파일 오류/재시도.
- OP-04: 추천→주기 선택→외부 연결; 미확인 상태 보장.
- OP-05: 삭제 요청→확인→로컬 처리; 실패 시 완료 표시 금지.

## 판정
- **Pass:** 실제 시연 또는 자동 검증으로 수용 기준 충족.
- **Partial:** 구현은 있으나 확인되지 않았거나 핵심 예외가 누락됨.
- **Fail:** 요구사항 미충족.
- **Not tested:** 실행/검증 불가. 성공으로 계산하지 않음.

Phase마다 `docs/TEST_RESULTS.md`를 작성·갱신한다. 결과에는 테스트 날짜, 환경, 수행 방법, 기대값, 실제값, 판정, 후속 조치를 기록한다.
