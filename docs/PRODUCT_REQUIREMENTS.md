## 기능 요구사항 (SSRD RQ)
| ID | 필수 사용자 경험 | Mock 경계 / 주의 |
|---|---|---|
| RQ-01 | 구강 상태 설문, 필수값 검사, 제출 | 누락 시 제출 불가; 실제 의료평가 아님 |
| RQ-02 | 시린이·잇몸·치아·입냄새 등 항목별 수준과 설명 | 데이터 없으면 0점 대신 평가 불가 |
| RQ-03 | 결과에 연계된 구강 관리 조언 | 조건 기반 예시 응답, 실패/저신뢰 안내 |
| RQ-04 | 교체용 팁 4종 중심 제품 추천, 추천 근거 | 존재하지 않는 제품 사양·의학적 효능 주장 금지 |
| RQ-05 | 양치 시간·점수·커버리지·기간별 이력 | 미연결/기록 없음/전송 오류 구분 |
| RQ-06 | 영상 선택·동의·모의 분석 결과 | 지원 형식/품질 검사, 실제 영상 판독 아님 |
| RQ-07 | 상품·배송 주기·구독 신청 흐름 | 가상 신청; 외부 확인 없으면 주문 완료 아님 |
| RQ-08 | 홈 대시보드 및 주요 기능 진입 | 미연결/미평가 상태 안내 |
| RQ-09 | 외부 판매 경로 안내/이동 | 실제 링크가 없으면 데모 채널, 임의 실거래 URL 금지 |

## 예외 요구사항
- **ONRQ-01**: 기기 연결/동기화 실패 — 상태, 재시도, 미연결 데이터 보존 규칙 확인.
- **ONRQ-02**: AI 분석 오류 및 저신뢰 — 허위 결과 금지, 재시도 또는 평가 불가.
- **ONRQ-03**: 주문/구독 연동 실패 — 미확인 주문을 성공 표시하지 않음.
- **ONRQ-04**: 개인정보 권한/삭제 — 동의와 로컬 기록 삭제, 부분 실패 시 완료로 위장 금지.

## 사용자 주요 흐름
1. 홈 → 설문 → 결과 → 조언 → 추천 제품.
2. 홈 → 기기 연결 시뮬레이션 → 양치 데이터 동기화 → 이력/상세 분석.
3. 양치 관리 → 영상 선택 및 동의 → 분석 중 → 데모 결과 또는 오류.
4. 제품 추천 → 상품 → 구독 주기 → 가상 신청/외부 구매 연결.
5. 설정 → 데이터 동의 확인 → 로컬 데이터 삭제.

## 제외 및 설계 원칙
- 실제 의료 진단, CNN 훈련/추론, 실제 BLE·기기 SDK, 실결제, 실주문, 서버 기반 사용자 인증, APK/iOS 테스트 배포는 이번 웹 프로토타입 범위 밖이다.
- SSRD의 초기 앱 배포/REST API/영상 보존기간 등 운영 요구는 실제 서비스를 위한 가정이다. 프로토타입은 어떤 항목을 Mock으로 대체했는지 투명하게 표시한다.
- 기획서에 없는 설문 문항, 추천 규칙, 제품 가격은 **데모 가정**으로 명시하고 `DECISIONS.md`에 근거를 적는다.
